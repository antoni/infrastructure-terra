## Completed

The initial repository contained only an untested `mountain_tile_backend` role
(`b7b694d`). Commit `d70e53a` prepares and tests its deployment path:

- Added `ansible.cfg`, `playbooks/mountain_tile_backend.yml`, an empty default
  inventory and `inventory/hosts.example.yml`. Actual host details belong in the
  ignored `inventory/hosts.local.yml`.
- Added controller dependencies, Makefile commands, deployment documentation and
  GitHub CI. The target must already have Python 3.9+, Docker and Compose; the
  role does not install Docker or issue certificates.
- Corrected tile serving to terrain-platform's
  `/tiles/<dataset>/<sha12>/{z}/{x}/{y}.<format>` URLs and nested
  `pmtiles/<dataset>/<sha12>.pmtiles` archives. The original release-ID routes
  and flat archive assumptions were incompatible with the pipeline.
- Added a shared content-addressed tile store. The indexer verifies archive
  content hashes, rejects immutable collisions and retains old versions. Hard
  links avoid duplicate bytes on one filesystem; cross-filesystem deployment
  copies once. Deployed archives must not be edited in place. Pruning is deferred.
- Corrected nested archive verification before activation. The smoke checker
  reads only the 127-byte header rather than loading each entire archive.
- Required matching release identifiers, publishable manifests and immutable
  `/releases/<release-id>/...` asset URLs before activation. Private synthetic
  rehearsals explicitly set `mountain_tile_backend_require_publishable=false`.
- Disabled legacy vhost cleanup by default and corrected its optional path
  expansion. Compose project names isolate test and deployment stacks. File owner
  and group are configurable so the local rehearsal needs no sudo.
